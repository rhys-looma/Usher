## Part 0: voting compiler

- `packages/core/src/compile/vote.ts`: up to three runs. The first labels the whole page. The second asks only about contested elements (more than one strong short-list candidate, or labelled consequential or needs_user). The third asks only about those the first two disagree on, or that either labelled risky. Majority per element; a risk tie takes the stricter risk, a key tie the short list's top candidate, else `custom.<slug>`.
- Agreement counts per element (runs, how many agreed on the key and the risk) go in the compile log (`task: vote_result`) and the map's `provenance.votes` (schema updated). Counts only.
- The keeper and the eval runner (`accuracy.ts`) use vote mode; the CLI stays single-pass (`--vote` to opt in).
- **Before/after against the human marks** (`reports/vote-eval.md`, `packages/core/scripts/vote-eval.ts`, $0.57 live). The 13 public forms of the complete marked run (69 elements) were compiled again, once with one run and once in vote mode, and each element was matched to its marked row by label. One run: 37 of 48 matched keys right (77.1%), 47 risks (97.9%). Vote mode: 39 of 50 (78%), 49 risks (98%). Vote mode changed none of the marked keys, so there is nothing new to mark. Both modes have the same 9 regressions against the 27 October marks: the model answers those differently today, with or without a vote. So on these forms vote mode is level on accuracy; what it adds is the per-element agreement counts, which show where to look. Vote runs per form: 1 to 3 (5 forms needed only one).
- Also in this PR, as groundwork for Part W: an optional `box` on map elements (position and size only), kept only when a compile asks for it (`boxes: true`).
- The keeper's test now expects the recompile to be followed by up to two vote runs.
- **Shipped** as [#92](https://github.com/rhys-looma/Usher/pull/92), deployed `73d50a223500` (both services, 140 s). Smoke test: every check that needs no site secret passed. The hosted health fill completed in 9.9 s (£66.91 a month); both remote agents completed the quote (3.6 s).

## Part W: walkthrough mapper ("Map my site")

- **Image check first.** muse-spark-1.3 accepts an image: shown a rendered word, it read it back ("LANTERN"). Recorded in `packages/core/test/fixtures/image-check.json` with its script and test.
- **W1, access and limits.** Signed-in owner of a claimed site, start page on that origin; the operator through `/admin` on the demo site only. One run per site per UTC day (`USHER_WALKTHROUGH_DAILY_LIMIT` raises it for the demo site only), one at a time, refused if today's spend plus $0.60 would pass the cap. The dashboard card shows the last run and greys the button with the reason. Test values by key or the generated test person, in the run's memory only; a tick for pressing the final consequential action.
- **W2, the run.** Knocks as `walkthrough:<site>`; per page: extract, explore each radio and select (first 12, up to 8 options each) and write `shown_if` from what appeared, label with Muse Spark in vote mode with the masked screenshot and boxes, run lookups and count the lists, fill, press forward and record `leads_to`. Stops at the first consequential action it isn't allowed to press. Held as a proposal with a diff against the current maps until the owner publishes.
- **W3, annotated viewer.** Boxes per element coloured by risk with the key as a tag, a table with conditions and `leads_to`, hover and focus linking both ways, every box a link to its row. Corrections inline behind a "Correct" toggle. The picker's public forms get the same view ("See how Usher reads this form"), drawn from the cached map's locators with no model call.
- **W4, corrections.** Stored in a new `corrections` table (migration 005) and the local compiler log, tagged `owner_verified`, with the element's structure as a small model sees it. `finetune:export` takes the owner's answer over model runs and counts owner-verified examples in `stats.json`; `--corrections` reads the production table, downloadable at `/admin/corrections.jsonl`.
- **W5, live view.** Server-sent events: masked JPEG frames and plain-words steps; keep-alive every 15 s; closes cleanly on the end; the run continues if the page is closed. Public read-only at `/demo/walkthrough` for the demo site.
